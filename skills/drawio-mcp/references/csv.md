# CSV 导入

`open_drawio_csv` 把表格数据转成图，适合**规则网格**：组织架构、简单清单、按列分组的条目。它不接受坐标，布局由编辑器决定。

## 1. 已验证的最小格式

```csv
# label: %name%
# style: rounded=1;whiteSpace=wrap;html=1;fillColor=#EEF4FF;strokeColor=#9DB8F2;fontColor=#1B1F24;
# connect: { "from": "id", "to": "id", "invert": false, "style": "edgeStyle=orthogonalEdgeStyle;html=1;" }
id,name
a,需求评审
b,方案设计
```

- `# label` 指定用哪一列做节点文字（`%列名%`）。
- `# style` 是所有节点共用的样式串；需要分角色时用多列 + 条件样式（draw.io 支持按列取值，本仓库未验证）。
- `# connect` 描述边：`from`/`to` 指向**列名**，不是固定值；上面的写法只是最小可打开样例，不代表"自连"语义已验收。
- 第一条非 `#` 行是表头；之后每行一个节点。

**证据等级**：能打开（返回 `type=csv` 的编辑器 URL），未做逐项渲染验收。复杂关系不要用 CSV。

## 2. 什么时候用

| 适合 | 不适合 |
|---|---|
| 组织架构（上级/下级两列） | 需要精确坐标 |
| 清单转节点（名称/负责人/状态） | 容器、泳道、分层 |
| 简单的父子/引用关系 | 多条边、条件分支 |
| 从 Excel/数据库导出的表格 | 每节点不同样式 |

## 3. 与 XML 的分工

1. CSV 先出"节点清单"草图；
2. 结构确认后转 XML（`references/recipes.md` 配方 6 的迁移方法）；
3. XML 才能表达容器、边归属、图例、精确布局。

## 4. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 图是空白 | 首行不是 `#` 指令或没有表头 | 保留表头行 |
| 节点文字是列名 | 没写 `# label` | 指定 `%name%` |
| 连线错乱 | `from`/`to` 填了固定 id 而不是列名 | 按列名引用 |
| 样式不生效 | 样式串少了 `html=1` 或分号 | 补齐分号与 `html=1` |
| 想要泳道 | CSV 不支持 | 改 XML |

完整语法以 draw.io 官方 CSV 导入说明为准；本页只覆盖已实测能打开的最小子集。
