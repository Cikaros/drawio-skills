# 布局规范

布局决定读者能不能一眼找到主路径。这里给的是**可执行的坐标规则**，不是审美口号。

## 1. 网格

```text
x = col * 180 + 40
y = row * 120 + 40
矩形 140×60    菱形 160×90    椭圆 140×60    圆柱 110×70
```

- 一个节点一个单元。
- 同列同 x，同行同 y；不要"差 5px 对齐"。
- 画布：A4 横向 1169×827；宽图用 1400×900。
- 页面左边距 40，上边距 40；标题占第 0 行。

## 2. 方向

| 场景 | 方向 |
|---|---|
| 流程、审批、状态机 | 自上而下（TD） |
| 流水线、时间线、数据流 | 从左到右（LR） |
| 架构分层 | 自上而下：接入 → 服务 → 数据 |
| 组织架构 | 自上而下；同级横向展开 |
| 泳道 | 横向泳道自上而下堆叠，流程从左到右 |

一张图只用一个主方向。回边（loop）走外侧，不要穿过主路径。

## 3. 间距

| 关系 | 间距 |
|---|---|
| 同层相邻节点 | 40 |
| 跨层（边长度） | 60–80 |
| 容器内边距 | 20 |
| 泳道子元素左边距 | `startSize + 10` |
| 标题与图体 | 30–40 |
| 图例与图体 | 40 |

节点之间宁可多留白，也不要靠线来"挤"。线是最后才用的分隔手段。

## 4. 交叉与绕行

1. **先改布局**：把相关节点放同一列/同一行，能消掉大部分交叉。
2. **再合并**：多条边指向同一区域时，用一个 hub 节点（网关/总线/注册中心）收口。
3. **最后才路由**：`routing:"libavoid"` 只重算预览连线，不改位置，也不会写回 `.drawio`；适合架构/泳道这类手放布局。
4. `postLayout:"elk"` 会重排节点，适合结构复杂但位置无意义的流程图。
5. **端口分开**：同一形状的多条边用不同 `exitY`/`entryY` 或不同边；一条进、一条出共用同一点会把两个反向箭头叠成一条线。
6. **走廊排序**：从同一源扇出到一行目标时，按目标从左到右把走廊从近到远排；每条边占独立 y/x 走廊，间距至少 12px。
7. **静态检查**：共享长段/原路折返是 `EDGE005`，穿框是 `EDGE006`；两者都修完再导出，不能只靠预览器临时避障。

判定：如果一条线穿过两个以上的框，就必须处理，不能"看起来还行"。

## 5. 容器

- 容器表达**边界**：系统、部署单元、网络区、团队。
- 三层是上限；再深改用多页。
- 容器标题写"是什么"，不写"包含什么"。
- 子元素坐标相对容器；让开 `startSize`。
- 跨容器边挂 `parent="1"`；同容器边挂该容器。

## 6. 泳道

- 每条泳道一个责任主体，不要"其他"。
- 泳道高度统一 150；子元素 `y=45`。
- 每个交接点只跨一次泳道；同一条消息不要来回跨。
- 泳道宽度 = `max_col*180 + 300`。

## 7. 对齐与视觉重心

- 主路径居中，旁支放右侧或下方。
- 结束节点统一在右下或正下。
- 图例固定放左下或右上，不要压主路径。
- 注释层与主体分离（独立层），避免遮挡。

## 8. 规模控制

| 节点数 | 建议 |
|---|---|
| ≤ 15 | 单页 |
| 16–25 | 单页 + 简化标签；或拆"总览 + 细节" |
| > 25 | 必须拆页；总览只保留主路径 |

拆页规则：总览（5–9 个节点）→ 每个子系统一页 → 关键流程一页。页名即导航。

## 9. 布局自检

- [ ] 所有节点在网格上，同列/同行对齐
- [ ] 没有两个节点重叠（lint `LAYOUT001`）
- [ ] 子元素都在容器内（`LAYOUT002`）
- [ ] 没有子元素压住容器标题（`LAYOUT003`）
- [ ] 主路径一条线走到底，不回头
- [ ] 没有边共享长段或原路折返（`EDGE005`）
- [ ] 边不穿过无关方块（`EDGE006`）
- [ ] 回边走外侧，不穿主路径
- [ ] 交叉 ≤ 2 处；同一形状的出入边使用不同端口
- [ ] 图例、标题不压节点
