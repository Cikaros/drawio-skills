# 可访问性

图不是只给"能看清颜色的人"看的。最低要求：**黑白可读、放大可读、有文字替代。**

## 1. 颜色

- 不用颜色作为唯一区分手段。分支同时给文字标签（是/否）、线型或位置。
- 文字与背景对比 ≥ 4.5:1；大字号（≥ 18）可 3:1。
- 避免红绿对立作为唯一编码；红/绿同时配文字或图标。
- 深色模式单独验证，不要假设自动反色一定可读。

## 2. 文字

- 最小 11；正文 12–14。
- 不用全大写长句（中文无此问题，英文注意）。
- 行距足够：draw.io 的 `whiteSpace=wrap` + 合适宽高，避免文字贴边。
- 标签不用纯缩写；首次出现给全称。

## 3. 形状与线型

- 形状语义要一致（菱形=判断），这样不依赖颜色也能读。
- 虚线/实线含义写进图例。
- 箭头方向清晰；双向关系用双向箭头，不要靠文字猜。

## 4. 替代文本

- 仓库里的图配一句 `alt`/图注：说明"这张图表达什么"，不是"这是一张图"。
- 交付文档里，图前后各有一段文字说明关键结论。
- 复杂图（> 15 节点）附一份文字版流程/清单。

## 5. 缩放与导出

- 导出 SVG（矢量）优先；PNG 至少 2x。
- 100% 缩放可读；不依赖放大才能看清标签。
- 打印版：白底、黑字、浅填充。

## 6. 结构

- 阅读顺序与视觉顺序一致：从上到下、从左到右。
- 主路径不要穿过其他节点；交叉越少越好。
- 容器标题在左上，符合阅读起点。
- 图例放在读者先看到的位置（左上/右上），不要藏角落。

## 7. 检查表

- [ ] 去掉颜色后仍能区分主路径/分支/异常
- [ ] 文字对比度 ≥ 4.5:1
- [ ] 最小字号 ≥ 11
- [ ] 虚线含义有图例
- [ ] 图有文字替代（图注/alt）
- [ ] 导出 SVG 或 2x PNG
- [ ] 深色模式下单独看过
- [ ] 100% 缩放可读，不需要放大
