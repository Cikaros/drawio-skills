# 图种选择与验收

## 1. 选择表

| 要表达 | 用 | 不用 |
|---|---|---|
| 步骤、分支、循环 | 流程图 | 架构图 |
| 谁在什么时候做什么 | 泳道图 | 流程图 |
| 两个维度都要（角色 × 阶段） | 交叉职能表（`shape=table`） | 嵌套泳道 |
| 系统/服务/依赖 | 架构图（容器 + 边） | 部署图（除非真讲部署） |
| 机器、网络、可用区 | 部署/网络拓扑 | 架构图 |
| 实体与关系 | ER 图 | 类图 |
| 类型与继承 | UML 类图 | ER 图 |
| 对象间时序消息 | 时序图（Mermaid） | 流程图 |
| 状态与迁移 | 状态机 | 流程图 |
| 层级分解 | 思维导图/树 | 架构图 |
| 汇报关系 | 组织架构图 | 泳道图 |
| 排期 | 甘特图 | 时间线（除非只讲里程碑） |
| 事件先后 | 时间线 | 甘特图 |
| 系统上下文 | C4 Context | 架构图（除非要细节） |

**判断口诀**：先问"读者要做什么决定"，再问"哪个维度最重要"，最后才选图种。

## 2. 各图种要点

### 流程图

- 一个入口、一个（或明确多个）出口。
- 每个判断两条分支都有去向；没有"悬空"分支。
- 回边只走一条，且标注触发条件。
- 异常路径要么画出，要么在图注写"异常略"。

验收：从入口能走到每个节点；无孤立节点；判断标签是"问题"，不是"动作"。

### 泳道图

- 一条泳道一个责任主体；不要"系统"和"后端"混用。
- 每个交接只跨一次；同一条消息不来回跨。
- 泳道内步骤从左到右，时间只增不减。
- 跨泳道边挂 `parent="1"`。

验收：每条泳道都有事做；没有"空泳道"；交接点能说清"谁交给谁"。

### 架构图

- 容器表达边界（系统/部署单元/网络区），不表达调用顺序。
- 外部系统在容器外。
- 边只画有意义的依赖，标注协议/数据（1–3 词）。
- 分层：接入 → 应用 → 数据；同层横向排。

验收：能指出每个服务的归属；没有"跨层直连"却无说明；外部依赖清楚。

### ER 图

- 实体名大写，字段小写；PK/FK 标在字段行。
- 关系用动词（places/contains），基数用鸦爪。
- 多对多要么画关联实体，要么注明。
- 不画与查询无关的字段。

验收：每个外键都有对应实体；基数与业务规则一致；没有孤立实体。

### 状态机

- 状态是形容词/名词（待支付），不是动作（支付）。
- 迁移标事件（支付成功），必要时加守卫条件。
- 每个状态可达；终态明确。
- 异常迁移（超时/取消）用虚线。

验收：从初始态可达所有状态；没有死状态；每个状态有出口或标明终态。

### 时序图

- 参与者 ≤ 7；多了分组或用 C4。
- 只画关键消息，不画内部实现。
- 激活条（activate）只标长生命周期。
- 异步消息用 `-->>` 或注明 async。

验收：消息顺序能读成故事；没有"魔法返回"（未画请求就返回）。

### 思维导图

- 根节点是主题，不是"图"。
- 每层 ≤ 7 个分支；同级同抽象层。
- 不加边标签，层级本身表达关系。

### 组织架构图

- 只画汇报关系，不画协作关系。
- 同级同宽同高；虚线框表示空缺/兼岗要图例。
- 姓名 + 角色，不要只写姓名。

## 3. 混合图的边界

可以混合，但要满足：

- 一种主图种，其他作为**注释**（图例、便签），不改变主结构。
- 例如架构图上标部署区域：区域用容器，不改成网络拓扑符号。
- 混用两种语义形状（如菱形既当判断又当网关）必须避免。

## 4. 一页放不下时

拆分顺序：

1. 总览（5–9 节点，只留主路径）
2. 每个子系统/阶段一页
3. 关键异常一页（可选）
4. 附录：术语、图例、数据字典

页名即导航：`总览` → `下单流程` → `支付与退款` → `附录`。

## 5. 图种与工具

| 图种 | 首选 |
|---|---|
| 流程图、状态机、时序、ER、类图、甘特、思维导图、时间线 | Mermaid（快） |
| 泳道、交叉职能表、架构、部署、网络、C4 细节 | XML（可控） |
| 行业图标（AWS/Azure/Cisco/P&ID） | XML + `search_shapes` |
