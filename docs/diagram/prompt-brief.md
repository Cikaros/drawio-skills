# 制图简报模板

让 AI 一次画对，比让它返工三次便宜。填完这 8 项再动手。

## 模板

```text
1. 目的：这张图要让人理解/决定什么？（一句话）
2. 受众：谁看？他们熟悉术语吗？
3. 范围：包含什么、明确不包含什么？
4. 图种：流程图 / 架构图 / ER / 泳道 / 状态机 / 其他
5. 关键内容：
   - 节点（名词）：
   - 关系（动词）：
   - 分支/异常：
6. 约束：
   - 画布：A4 横向 / 宽屏 1400×900 / 不限
   - 方向：自上而下 / 从左到右
   - 必须出现：图例 / 标题 / 版本号 / 负责人
7. 风格：默认 calm / 经典 draw.io / 极简黑白 / 品牌色 #xxxxxx
8. 交付：只要预览 / .drawio 文件 / 导出 SVG / 多页
```

## 示例（差）

> 画一个订单系统的架构图。

问题：没有目的、受众、边界、图种细节；AI 只能猜，产出必然是"所有东西都画上"。

## 示例（好）

```text
1. 目的：让新同事 5 分钟内理解下单主链路和外部依赖。
2. 受众：后端新人，熟悉 HTTP/DB，不熟悉内部服务名。
3. 范围：包含 Web、API 网关、订单服务、订单库、支付网关（外部）、消息队列；
   不包含监控、CI/CD、历史遗留的报表服务。
4. 图种：架构图（容器表示部署单元）。
5. 关键内容：
   - 节点：Web 前端、API 网关、订单服务、订单库、支付网关、消息队列
   - 关系：Web→网关 HTTPS；网关→订单服务 RPC；订单服务→订单库 SQL；
     订单服务→支付网关 HTTPS；订单服务→消息队列 发布
   - 异常：支付超时进入补偿队列（用虚线）
6. 约束：A4 横向；自上而下分层；必须有图例说明虚线。
7. 风格：默认 calm 配色，外部系统灰色。
8. 交付：.drawio 文件 + 预览第 1 页。
```

## 追问清单（信息不足时）

只问会改变结果的问题，一次问完：

1. 这张图给谁看，看完要做什么决定？
2. 有没有必须保留的既有结构/命名？
3. 需要哪些外部系统/角色？
4. 交付格式与画布尺寸？
5. 有没有品牌色或模板？

不要问"你想要什么颜色""要不要加阴影"这类可由规范决定的问题。

## 反模式

| 说法 | 问题 | 改问 |
|---|---|---|
| "画详细一点" | 无法验收 | "必须出现哪 6 个节点？" |
| "参考一下竞品" | 没有边界 | "要借鉴它的分层还是配色？" |
| "随便画" | 返工源头 | 用默认规范，并声明假设 |
| "越漂亮越好" | 不可执行 | "给谁看？打印还是屏幕？" |

## 交付时的假设声明

信息不全时，先按默认规范做，并在交付说明里列假设：

```text
假设：受众为后端新人；画布 A4 横向；外部系统用灰色；未包含监控。
如需调整，改这三处即可：容器边界、外部系统清单、是否加异常路径。
```
